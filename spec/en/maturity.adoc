= Rules as code maturity
include::_fpsot-terms.adoc[]

This page is informative.
It sets no rule.
It gives a scale that helps a body see where its rules stand.
It also notes the engines and languages that {abbr-fpsot-first} watches.

== A scale of five levels

{abbr-fpsot} defined this scale itself.
The link:https://www.oecd.org/en/publications/cracking-the-code_3afe6ba5-en.html[Organisation for Economic Co-operation and Development], OECD, published a study on rules as code in 2020.
This scale is not an OECD scale, nor the scale of any other body.
The research for this specification found no maturity scale in OECD work.
A later mapping to an OECD framework remains possible.

[cols="1,2,5,3",options="header"]
|===
|Level |Name |What holds |Rules
|0 |Hidden |The rules live only in code, with no citation, no dates and no tests that an expert can read. |None
|1 |Cited |Each rule version cites its legal source, its presumptions and the status of its interpretation. |DEC-030 to DEC-033
|2 |Dated and tested |Rule versions carry both clocks, parameters live in dated files, and experts help write the scenarios. Each version has a frozen corpus. |DEC-034 to DEC-037, DEC-080, DEC-081
|3 |Published |The source, the scenarios, the results of the conformance suite and the general explanation are public. |DEC-038, DEC-058, DEC-083
|4 |Co-drafted |Drafters of the law and authors of the rules write both together, and test each draft against the corpus before adoption. |DEC-085 and drafting practice
|===

Each level includes the levels below it.
A body can state its level for each decision type in the description of that type.

== Notes on engines and languages

These notes record the state of some tools at the date of this version.
They are not advice to use any tool, and no rule of this specification names one.

* Catala is a language for writing law as code, from Inria.
The French family benefits agency, CNAF, link:https://caf.fr/professionnels/presse/publications/la-cnaf-et-inria-s-engagent-ensemble-pour-developper-catala-une-solution-souveraine-de-calcul-des[chose it with Inria] in June 2026.
link:https://arxiv.org/abs/2103.03198v2[A study] that rewrote part of the French family benefits in Catala found a bug in the official implementation.
The research could not confirm a Java backend.
If one appears, a Catala program could become a rule provider behind the same contract.
* DMN 1.6 is a formal standard of the Object Management Group, and DMN 1.7 is a beta.
The results page of the compatibility kit still states that it reflects DMN 1.4.
* link:https://github.com/goldmansachs/jdmn[jDMN] generates Java code from DMN models when the artifact builds, which fits DEC-003.
The kit results list it with 3,391 of 3,407 tests passed.
* The Apache KIE projects include Drools and Kogito.
They are still in incubation at the Apache Software Foundation, as its link:https://whimsy.apache.org/board/minutes/KIE.html[board minutes] show.
* The link:https://web.archive.org/web/20251028192831/https://forum.camunda.io/t/important-update-camunda-7-community-edition-end-of-life-announced/50921[Camunda forum] announced that the community edition of Camunda 7 gets no releases after version 7.24 of October 2025.
* OpenFisca is a Python library for tax and benefit rules over dated parameters, and DEC-037 follows its model.
* Blawx, used in Canada, encodes legislation as logic programs.
The link:https://oecd-opsi.org/innovations/new-techniques-for-building-and-using-legal-encodings-in-the-drafting-room/[OECD case study] describes its use in a drafting room.

A body can pick any of these tools, or none.
The contract, the records and the conformance suite stay the same.
